# Zecpath-AI Developer Onboarding Guide

Welcome to the Zecpath-AI engineering team! This guide will get you set up to run, test, and contribute to the AI microservices locally.

## 1. Prerequisites & Environment
Ensure you have the following installed on your machine:
- **Python 3.10+** (Required for modern type hinting and `dataclasses`)
- **Docker & Docker Compose** (Required for the Machine Test Sandbox execution)
- **Git**
- **Windows Users:** Ensure you are using PowerShell/CMD as administrator if installing C-extensions.

## 2. Local Setup Instructions

### Clone & Virtual Environment
```bash
git clone https://github.com/Zecpath-AI/aiproject.git
cd aiproject
python -m venv venv

# On Windows:
venv\Scripts\activate
# On Mac/Linux:
source venv/bin/activate
```

### Install Dependencies
Our dependencies include heavy NLP models. Be patient during the installation.
```bash
pip install -r requirements.txt
pip install waitress  # Production WSGI server
```

### Download NLP Corpora
Zecpath-AI uses NLTK and spaCy for conversational analysis. 
```bash
python -m nltk.downloader vader_lexicon
python -m spacy download en_core_web_sm
```
*Note: The codebase has built-in soft-dependency fallbacks. If `spacy` fails to load due to Windows Application Control (DLL issues), the system will gracefully fall back to basic regex parsing.*

## 3. Repository Structure

The codebase is organized by Domain-Driven Design (DDD) principles rather than framework structures:

- `api/`: Flask API endpoints (`hr_interview_api.py`) exposing the AI engines. Contains standardized JSON error handlers.
- `utils/`: The core algorithmic scoring engines (`unified_scoring_engine.py`, `tech_scoring_engine.py`, `confidence_analyzer.py`, `malpractice_detector.py`).
- `config/`: JSON configuration files for engine weights and thresholds. **Note:** Configs are cached in memory using `@lru_cache`. If you change a config, you must restart the server.
- `interview_ai/`: The conversational finite state machine (`conversation_flow.py`).
- `docs/`: The complete system documentation. Start with `ZECPATH_TECHNICAL_HANDBOOK.md`.
- `tests/`: Automated unit and integration tests (specifically targeting edge cases and stabilization).
- `demo/`: Contains `simulate_full_pipeline.py`, which mocks a frontend UI and processes 3 distinct candidate personas (Strong, Weak, Suspicious).
- `reports/`: The destination folder for the polished Markdown hiring reports generated by the AI.

## 4. Running the System Locally

### Run the End-to-End Demo Simulator
To see the system in action without spinning up a frontend client, run the simulation script. This feeds pre-written candidate answers directly into the NLP state machine and outputs Markdown reports.
```bash
python demo/simulate_full_pipeline.py
```

### Run the Production API Server
Do **not** use `flask run` or `python app.py` for anything other than extreme debugging. Zecpath-AI uses `waitress` to handle concurrent requests safely.
```bash
python production_server.py
```
*The server will start on `http://0.0.0.0:8080` and output standardized logs to `logs/production.log`.*

## 5. Testing & Quality Standards

We use `pytest` for all automated testing. You are required to maintain a **100% pass rate** on the stabilization test suite.

```bash
# Run all tests
pytest tests/

# Run specifically the stabilization (edge-case) tests
python tests/test_stabilization.py
```

### Mandatory Code Guidelines
1. **Type Hinting:** All new functions must include strict Python type hints (`from typing import Dict, List, Optional`).
2. **Bounds Clamping:** If you modify a scoring engine, you must use the `_clamp()` function to ensure scores never exceed `1.0` or drop below `0.0`.
3. **API Idempotency:** Any API endpoint that mutates state must be safe to retry.
4. **Fail-Safe Processing:** Wrap external dependency calls in `try/except` blocks and return a neutral score on failure, rather than crashing the interview.
5. **Standardized Errors:** Always use the `_error_response(code, message)` helper in API routes. Never return raw string errors.
